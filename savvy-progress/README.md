# savvy-progress

A Claude Code mod: a progress bar above the prompt and a live panel of subagents. Made for the [savvy-flow](https://github.com/johnnyvizz/claude-kit/tree/main/plugins/savvy-flow) skill, and useful with any subagents.

**Origin:** by [johnnyvizz](https://github.com/johnnyvizz), MIT (see [LICENSE](LICENSE)). Copied from [johnnyvizz/claude-kit](https://github.com/johnnyvizz/claude-kit/tree/c871c153ead54ad9547cc717d0f3e5a676c73986/plugins/savvy-progress) at commit `c871c15`, version 1.2.1. 4A-Mods changed three things: this README, in 1.3.1 the run founded for a subagent the session never saw start (`foundRun` in the `turn.step` and `turn.complete` hooks, `addUnseen` in a `classic.SessionStart` hook for `/clear`, and `roundOf`, which `agent.spawn` now shares; tests in `hooks/auto.test.ts`), and in 1.3.0 the bar that draws without a reported plan (`waveOf`, `autoFlow`, `bandFlow` and the `dismissed` state in `hooks/register.tsx`, at the drawing, plus `resumedLast` in the `turn.step` hook; tests in `hooks/auto.test.ts`). Upstream changes reach 4A-Mods only after someone reads them and copies them here.

**Without savvy-flow** set `autoOpen` to `any`, or the panel opens only on `/agents-info`.

- **Progress bar**: the flow's title, phase, accepted tasks out of planned, and a button with the crew size that opens the panel. It appears once something reports progress (savvy-flow does) or a `savvy-*` worker starts.
- **Bar without a plan** (4A-Mods, 1.3.0): when nothing reported a plan and two or more subagents run in one wave, the bar draws by itself, titled "Subagents", with finished runs out of all runs of the wave (a failed run counts as finished). A wave begins with a subagent started while no other runs, and lasts until the next such start. A subagent whose end the engine never reports (the engine reports an aborted one too) would keep its wave open; the dismiss hides it. A finished subagent that gets a follow-up joins the current wave. A reported plan that is still open always wins, and so does the unnamed `savvy-flow` bar a `savvy-*` worker starts. Once the reported plan is finished, one running subagent is enough for its wave to show over the plan's Done, and the bar never says Done while a subagent of the session runs (1.6.2): with that wave dismissed, no bar draws until it ends. Dismissed, the bar stays away for the rest of the wave, and from a later wave that the dismissed wave's first subagent joins through a follow-up. The crew button counts every subagent of the session, not only the wave.
- **Steps of a few subagents** (4A-Mods, 1.7.0): with three subagents or fewer the bar counts their own steps instead of the subagents, and says Steps, not Tasks, once one has reported: one agent at 5/8 shows 5/8, two at 5/8 and 2/5 show 7/13. That holds for the wave without a plan and for a reported open plan of at most three tasks; a plan task takes the latest run that carries its title, else a run of the wave that no task names. Each subagent has its own part of the bar, as wide as its total and filled by its done, in its own colour (violet, teal, orange by place) with a gap of track between parts. A subagent that has not reported counts 0/1 while it works, so its report only adds to the total; one that ended counts in full (1/1 without a report, a failed one too, as the wave counts it finished), and a plan task with no run counts 1/1 when the plan's accepted count covers it. A changed total is read as it stands now. With four or more the bar counts subagents as before. While the flow is open the bar never reads 100%: a worker at its last step that still works shows 99%, and Done stays the finished flow's. A lone subagent with no plan still draws no bar (`AUTO_MIN`).
- **Subagents from before a clear** (4A-Mods, 1.3.1): `/clear` empties the list of runs while the subagents go on. The ones still at work get a row again right after the clear, with the description and type the engine lists for them; their model shows with their next model request. A finished one that a follow-up wakes gets its row with that request, or at its end. Tokens, cost and time of such a row count from the moment it was made, not from the subagent's real start; one first seen at its end gets that turn's tokens and no time. The same gives a row to a skill that runs in a fork, which the engine lists as an agent though nothing spawned it. An agent the engine does not list (a workflow's agent, a fork the engine or another mod makes) gets no row. A plan reported before the clear (a handoff's auto clear too) is kept aside (1.6.3): the band goes with the conversation, and the next `progress` call that names no other title, or a `savvy-*` worker started before any call, goes on with the plan, its title, tasks and counts. A new title, a finished plan or a dismiss lets it go.
- **Agents panel** (`/agents-info` toggles it; `/agents-info open` opens it or brings it forward without toggling): running, finished and planned subagents with model, effort, task progress, context, estimated cost and time. Working crabs walk, and each savvy tier animates its prop: the astronaut floats, the detective sweeps the magnifier, the engineer turns the wrench, the chef tosses the omelette, the racer runs with a fluttering flag. Other agents dress for the role their name says: a reviewer or judge strikes a gavel, an admin agent (lisa, invoice) works a calculator, a marketing one (watson, ads) shows a rising chart, a publisher snaps a camera, a writer scribbles with a quill, a fact-checker ticks a clipboard, the caveman crew swings a club, Plan draws a blueprint, web-fetch flies an envelope. An agent with no role wears the tier its model and effort match (Fable, Opus xhigh/high/medium, Sonnet or Haiku). At the top of the desktop panel the main agent has an avatar of its own, dressed for the folder the chat runs in: John Watson (`john-watson`) in a hoodie and headset, Lisa Stark (`Lisa Stark`, `Stark`) with a sleek bob and gold glasses in an emerald blazer, Greg (`greg-publisher`) with a beanie and camera, Irene Adler (`irene-adler`) in a feathered hat; any other chat is Claude with a crown and cape. Its pose follows the main loop: thinking during a turn, working while it edits or runs commands, handing out tasks while subagents run, waving when it waits for you. `prefers-reduced-motion` stops them.

## Tools it adds

- `mcp__savvy-progress__progress`: the orchestrator reports the plan, phase and accepted tasks. Only the main session can: a call from a subagent is ignored, so a worker cannot rename, finish or reset the flow.
- `mcp__savvy-progress__step`: a worker reports its own steps (`done`, `total`, `note`). A worker that does not report shows its context fill in grey instead. The tool is listed up front rather than behind ToolSearch, and every subagent gets one line at the end of its brief asking for these reports (a brief that already names the tool is left as it is).

Cost is a rough estimate from token counts and a built-in per-model price table (`PRICES` in `hooks/register.tsx`, list prices as of 2026-10-10), not a bill. Cache writes are priced at the 1-hour rate, which is what Claude Code writes on a subscription; a session that writes 5-minute entries is overestimated there.

## Settings

`language`: `auto` (default), `en`, `ru` or `he`. Hebrew draws the bar and the panel right to left. `auto` follows Claude Code's `language` setting, then the system locale, and falls back to English. Set it in `/config`, or, for a mod loaded by hand, in `~/.claude/settings.json`:

```json
{ "pluginConfigs": { "savvy-progress": { "options": { "language": "ru" } } } }
```

`autoOpen`: `savvy` (default) or `any`. With `savvy` the panel opens by itself when a `savvy-*` worker starts or a plan is reported. With `any` it also opens, once per session, when any other subagent starts. `/agents-info` toggles it either way.

Install instructions are in the [repository README](../README.md).
